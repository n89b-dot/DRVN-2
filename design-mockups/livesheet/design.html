10 — ONE SPRING, THREE DURATIONS
STAGGER 0 — 0MS
STAGGER 1 — 70MS
STAGGER 2 — 140MS
--spring—The one easing. Device spring: fast out, long settle, no overshoot.
--t-fast—Colour, background, press.
--t-move—Tiles, sheets, order rows, toast travel.
--t-draw—Rules drawing themselves in — scaleX(0 → 1) from the left origin.

Sequence: the drawing draws itself, then the data starts moving. .rv springs in (--t-move, staggered 70ms per data-stagger index), .dimline-h draws over --t-draw with a 120ms lead-in, and the .live-word underline lands at 400ms. Reveals fire once — the observer unobserves each element.

11 — LIVE BEHAVIOUR WATCH THE NUMBERS
[data-count]00 → target over 900ms, ease-out cubic, then stops. For values that are true but newly arrived.
[data-tick]71Every 4200ms, a 40% chance of +1 with a 900ms flash to --live. Never decrements. This is what makes the sheet feel watched.LIVE
[data-seconds]—H:MM:SS, hours only when non-zero, decrements every 1000ms, stops at zero.
pulse 2.2S EASE-IN-OUTLive dots on .capsule, .bar__link, .livedim--live.
draw (skeleton)1.5s gradient sweep — ink being drawn left to right. Never a spinner.

prefers-reduced-motion: reduce obligations — CSS and JS, both required. CSS: .rv renders at rest, .dimline-h renders drawn, every pulse stops, the skeleton sweep stops, the live-word underline is static. JS: reveals apply immediately without the observer, [data-count] prints its final value, [data-tick] prints its value and never starts its interval. Countdowns keep running deliberately — a countdown is information, not decoration.

31 — CONTRAST, HONESTLYTWO PAIRS FAIL
--ink on --paper13.6 : 1  DAY
--on-ink on --ink14.7 : 1  DAY
--dim on --tile3.5 : 1 DAY · 5.0 : 1 NIGHT
--live on --paper3.4 : 1 DAY · 5.4 : 1 NIGHT
--live on --live-tint3.2 : 1  DAY
--ok on --ok-tint4.2 : 1  DAY

--dim is not a body-text colour in DAY

3.5:1 fails AA for text. It is acceptable for microlabels and non-essential metadata whose content is duplicated elsewhere. It is not acceptable for the running prose that currently uses it — .pagehead .sub, .alert p, .undrawn p, .step__d, .drop p. Production fix: darken DAY --dim to ≈ #6B6E78 (4.7:1). One token, no component changes. NIGHT already passes at 5.0:1.

--live must never be the only carrier

At 3.4:1 on DAY paper, a red value fails AA for small text. Every live value in the system is therefore redundantly coded: a pulsing dot, a "LAPSES IN" microlabel, or a state change alongside the colour. .chip--live at 3.2:1 is the weakest pair in the system — chips are redundant labels by design, but production should darken the chip foreground rather than lighten the tint, which would weaken the state read.

Method: WCAG 2.x relative-luminance ratios computed against the tokens as declared, with alpha tints composited over --tile. Rule for new tokens: any colour proposed for text must be measured against --paper and --tile in both themes before it enters the file.
