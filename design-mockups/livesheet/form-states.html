SHEET 98 — SPEC · INPUT, VALIDATION, SUBMISSION, REGRET

Every state a field
can be in.

The empty-states spec covers what happens when there's no data. This one covers what happens when there's wrong data — and what happens after the user commits it. One governing principle: the sheet never loses a keystroke the user typed, and never tells them off while they're still typing.

01 — REST & FOCUS RELEASE A PART

Where: every text input on the platform. Rule: the focus ring is the browser's :focus-visible outline in --live, 2px at 3px offset — never removed, never restyled per-form, and never replaced by a colour change alone. Labels sit above the control as a mono microlabel and stay visible when filled; placeholders are examples, never labels. Hover changes nothing: a field is not a button.

02 — FILLED & READ-ONLY SHEET C-0416

Rule: a filled field looks identical to a rest field with a value in it — no "success" green just for having text. A read-only field keeps full contrast on the label, dims the value, stays focusable and copyable, and always carries a hint naming what owns the value. Read-only is never used to mean "you can't do this yet" — that is state 03.

03 — DISABLED, WITH A REASON
CHECK STATUS

Rule: a disabled control must always be accompanied by the reason it is disabled and, where one exists, the action that enables it. A disabled field with no explanation is a bug, not a state. Disabled controls stay in the DOM and keep their label so the form's shape doesn't change when they unlock.

04 — REQUIRED VS OPTIONAL

Rule: required is marked with a --live asterisk on the label; optional is marked with the word "(optional)" in lower-case mono. Never both conventions in one form, and never mark nothing — a form where most fields are required marks the optional ones and says so once at the top. Money fields use a fixed $ prefix inside the control so the user never types the symbol.

05 — HINT + COUNTER NEAR LIMIT 80 MAX

Rule: the counter is silent until 90% of the limit (72 of 80 here), then turns --live and stays visible. It counts up to the limit, never down from it, and the control hard-stops at the limit rather than accepting text it will later truncate. Type into it to see the threshold flip.

06 — INLINE ERROR, AFTER BLUR INTERACTIVE

Where: every validated control. Rule: validate on blur, never on keystroke — a field the user is still typing into has not failed yet, it is unfinished. Once a field has been marked invalid it switches to validate-on-input, so the error clears the moment it is fixed and the user is never punished for a corrected mistake. The error message names the expected format, not the violation ("Enter whole dollars", not "Invalid input").

07 — SUMMARY AT THE TOP 3 TO FIX

Three lines need attention before this listing goes live

Asking price — not a number · Handle — already taken · Floor price — above the asking price

Where: any form over six fields, and every form after a failed submit. Rule: the summary renders only after a submit attempt, is placed above the first field, receives focus, and is announced via role="alert". Each entry is an anchor to the field's id, and following it focuses the control — not just scrolls to it. The count in the header is exact; the summary disappears the instant the last error clears.

08 — ASYNC CHECK: PENDING → RESULT INTERACTIVE

Rule: async checks are debounced 400ms after the last keystroke, then show a pending row that reserves its own height so nothing below jumps when the answer lands. The submit button is not blocked while a check is in flight — it queues, and the server is the final arbiter. A failed network call is not a failed validation: it reads "Couldn't check right now — we'll confirm on save", never "taken". When taken, offer at least two free alternatives.

09 — CROSS-FIELD ERROR TWO FIELDS, ONE RULE
Your floor of $620 is above your $540 asking price — nobody could buy it.

Rule: a cross-field error attaches to the field the user most recently touched, not the first one alphabetically, and the message states both values so the conflict is legible without scrolling. Only one of the pair is marked invalid — marking both implies both are wrong. The rule is re-run when either field blurs.

Rule: client-side validation is a courtesy; the server is the authority, and a server rejection must render in the same visual language as a client error so it doesn't read as a crash. It names the conflicting record, and gives the correct route forward — never "Error 409".

11 — IDLE → PENDING → FILED INTERACTIVE

FILED — REV 18
ListingSabelt bucket seatLive in the market · $310 askingVIEW

Rule: submit moves through exactly three visible states. Pending: the button becomes non-interactive and states the verb in progress ("Filing…"), the form's inputs go read-only so nothing can be edited mid-flight, and no spinner replaces the page. Success: the form is replaced by the record it created — a stamped line the user can act on — never a bare "Saved!" alert. Pending must be reachable within 100ms of the click; if the request resolves faster, the pending state is still shown for a minimum of 300ms so it doesn't flicker.

12 — SUBMIT FAILED SERVER-SIDE INTERACTIVE

Rule — the one that matters most: on failure every value the user typed is preserved, exactly as typed, including the invalid ones. The form is re-enabled, the error says what happened and what to do, and the same button retries the same payload. Never redirect away from a failed form. Never clear a field to "reset" it. Idempotency keys are attached at first attempt so a retry cannot create two listings.

13 — TWO-STEP CONFIRM IRREVERSIBLE
ListingSabelt bucket seat$310 asking · 3 offers on the table · 41 watching

Deleting removes 3 live offers and the part's sale history

The provenance line stays on the car sheet, but the offers, the watcher list and the price history are gone for good. If you just want it off the market, end the listing instead — that's reversible.

Rule: a confirm dialog is only worth showing if it demands an intentional act — typing the word, not clicking a second button in the same place the first one was. The dialog states the specific, counted consequence ("3 live offers"), never "Are you sure?", and always offers the reversible alternative as a peer action. The destructive button stays disabled until the typed confirmation matches exactly, case-sensitive. Cancel is the safe default and is what Escape does.

14 — UNDO INSTEAD OF CONFIRM INTERACTIVE
T3
Garrett T3 hybrid — fresh rebuild
$540 ask · 2 offers · 41 watching

Rule: if an action is reversible, do it immediately and offer undo — do not interrupt with a confirm. The undo affordance lives in a persistent bar next to the affected row (not only in a toast that can be missed), runs a visible 10-second countdown, and the destructive write is not committed to the server until the window elapses. Undo restores the exact prior state including offers and watcher count. Confirm dialogs are reserved for the un-undoable — see 13.

15 — LEAVING WITH UNSAVED WORK

You have 4 unsaved changes on this sheet

Price, condition note, two photos. Leave now and they're kept as a draft for 30 days — nothing goes public.

Rule: the warning fires only when the form is genuinely dirty — a field touched and returned to its original value is clean. It counts the changes and names them, and because DRVN autosaves drafts it can promise where the work goes rather than threatening loss. Three options in fixed order: save, discard-by-leaving, stay. Never a bare browser beforeunload string as the only defence.

16 — AUTOSAVED DRAFT FOUND DRAFT · 2 DAYS AGO

Picking up where you left off

An unfinished listing for the KW Variant 2 coilovers — 6 of 9 fields and 3 photos, autosaved Monday 20:14.

Rule: the draft is offered, never auto-applied — silently repopulating a form the user thought was blank is worse than losing it. The banner states how complete the draft is and when it was saved in absolute local time. "Start fresh" does not delete the draft immediately; it moves it to drafts for the remainder of the 30-day window.

17 — OPTIMISTIC UPDATE, ROLLED BACK INTERACTIVE
KW
KW Variant 2 coilovers
$680 ask · not reserved

Rule: optimistic writes are allowed for low-stakes, single-row changes (reserve, watch, follow) and never for money movement. When the write fails, the row flashes back to its prior value in place — it does not vanish, and the page does not reload. The failure note replaces the row's meta line, states the value has been reverted, and the control returns to its pre-click state so a retry is one click. Press Reserve to watch it fail and revert.
